About Agents × llm-d Demo
Orchestrating high-density AI agents across TPUs and GPUs
Sim Standalone

This application demonstrates llm-d (an open-source, Kubernetes-native inference router) operating alongside GKE Agent Substrate. It showcases prefix-cache-aware routing, sub-second agent suspend/restore, and balanced serving across TPUs and GPUs.

Live Mode
GKE
  • GKE Agent Substrate: Manages 1,000 real agent sandboxes in isolated gVisor runtimes across Kubernetes worker nodes.
  • Real Hermes Agents: Runs NousResearch hermes-agent inside Python containers. SQLite session history survives across suspend/resume cycles.
  • Golden Snapshot: Pre-warms the agent runtime to absorb ~3s of Python import setup, snapshotting memory to SSD/GCS for fast restore in <2.8s.
  • llm-d Routing: Sandboxes query the llm-d gateway, which balances traffic across live vLLM model engine pods on TPUs and GPUs.
  • Live Telemetry: Scrapes Prometheus metrics directly from serving pods and the in-cluster driver.
Simulation Mode
Model
  • Runs Standalone: Completely self-contained in Cloud Run or local containers—no Kubernetes cluster, accelerators, or VPC peering required.
  • Discrete-Event Engine: mock_server.py simulates 1,000 agents traversing the identical state machine from suspended to running.
  • Calibrated Metrics: Latencies, TTFT distributions, and cache hit ratios are directly fitted from real cluster benchmark runs on GKE.
  • Interactive Tuning: Dynamically adjust TPU vs. GPU traffic splits, simulated node pool topologies, and agent pacing in Settings.
  • Zero Accelerator Cost: Full fidelity of the interactive UI experience without consuming expensive hardware hours.
Prefix-Aware Routing llm-d routes multi-turn sessions to the pod caching the prompt prefix, avoiding re-prefill penalties.
Sub-Second Restores Agent Substrate pauses idle agents to storage and restores them in under a second upon receiving a new turn.
Heterogeneous Pools Unified traffic steering across TPUs and GPUs without modifying application agent code.
KV Cache Tiering Spills evicted agent prefixes from hot HBM to Host DRAM and restores at 28–42 GB/s.
